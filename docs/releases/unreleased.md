# Unreleased Changes

Last updated: 2026-09-05

- ACP (Agent Client Protocol) integration is now feature-complete and replaces the legacy AI assistant panel in the right-side dock: streamed markdown replies, collapsible agent thoughts, tool-call cards with diffs/output/locations, inline permission approval, live plan card, session modes, slash-command completion, and context-usage badge. External coding agents (Codex first) run as subprocesses over ndjson JSON-RPC; eShell now serves `fs/read_text_file` / `fs/write_text_file` for agents and forwards `session/request_permission` to the user. New commands `acp_permission_respond` / `acp_session_set_mode`; `acp_agents.json` gains optional `cwd` and `mcpServers`. The AI config dialog entry moved to the left toolbar Config section. See the [ACP Agent Guide](guides/features/acp_agent.md).
- The ACP panel now handles agent sign-in: when session creation fails with AUTH_REQUIRED (e.g. Codex without credentials), the connection stays alive and the panel shows a sign-in card with one button per advertised auth method (ChatGPT OAuth etc.) plus manual fallbacks (codex login / CODEX_API_KEY / OPENAI_API_KEY in `acp_agents.json`). New `acp_agent_authenticate` command runs the ACP `authenticate` flow and creates the session on success.
- ACP panel gains session history and image prompts: transcripts auto-persist to `.eshell-data/acp_sessions/` (new `acp_history_*` commands) with a history browser (view read-only, resume, delete); resuming uses native ACP `session/load` when the agent supports it (full context restored via replay) and falls back to a fresh session otherwise; the composer accepts image attachments (picker + paste) gated on the agent's `promptCapabilities.image`. Image attachments are normalized client-side (downscaled to ≤1568px and re-encoded when oversized) to avoid Codex-side "image content omitted" size placeholders.
- eShell now ships a built-in MCP bridge: a loopback streamable-HTTP MCP server (random port, per-run bearer token) exposing `list_ssh_profiles`, `list_shell_sessions`, `execute_command`, `read_remote_file`, `write_remote_file`, `list_remote_dir`, and `get_server_status`. ACP agent sessions get the endpoint injected automatically (per-agent opt-out via `"eshellTools": false`), so agents can operate the servers already open in eShell — scoped to user-opened sessions, credentials never exposed, destructive calls gated by the agent's permission prompts.
- The ACP agent list now reloads whenever the dock opens, so `acp_agents.json` edits (e.g. adding Claude Code / OpenCode entries) show up without an app restart.
- The ACP panel header now shows each agent's brand mark: the crude native `<select>` is replaced by a proper picker (logo + name + running-process dot, and a full-width popover listing every configured agent with its logo, spawn command, live state, keyboard navigation and a tooltip explaining why the choice is locked while a session runs). The session-mode `<select>` became a matching picker but moved out of the header down to the bottom-right of the composer (Codex/Claude Code style: pill trigger, menu opens upward), and the image attach button is gone — images are pasted into the composer instead. Agent logos also appear in the session-history list and on the start screen. Official marks ship for Codex/OpenAI, Claude Code, OpenCode, Gemini and Qwen (`src/lib/acpAgentBrands.js`); agents that cannot be identified fall back to a neutral icon rather than a wrong logo.
- The ACP panel now exposes the agent's own session config options — model selection and thinking/reasoning effort included — as pills in the composer footer. New `acp_session_set_config_option` command; `configOptions` is forwarded from `session/new` / `session/load` and kept live through `SessionUpdate::ConfigOptionUpdate` (agents push the full set, so it is replaced wholesale). Everything lives behind one settings button whose menu lists a row per setting and flies the values out to the side on hover, and menus now anchor beside their own trigger instead of all opening at the composer's bottom-right corner. Only the `model` and `thought_level` categories are surfaced: the `mode` mirror is dropped (`session/set_mode` already drives it), `model_config` is dropped (that is where both agents put "fast mode"), and unknown/absent categories are dropped (Codex's `collaboration_mode`, Claude Code's persona selector). Probed against real agents with the new `scripts/acp-probe.mjs` — note the advertised set is dynamic, not a fixed per-agent list: the same Claude Code offers `fast-mode` on an Opus model and an uncategorized `agent` selector on a custom one, which is why filtering is by category rather than option id. Note the wire shape — `session/set_config_option` takes the value bare at the top level (`"value": "high"`), and codex-acp rejects a nested object with -32602; a regression test pins it.
- Fixed an unrecoverable ACP panel state: because the Rust agent registry outlives the webview, reloading the frontend (dev HMR, devtools) left the agent process running while the panel reset to idle, so starting again failed with "acp agent `x` already has an active session" and nothing in the UI could clear it — the stop button only rendered while `ready`, and `stop()` resolved its target from frontend state that the reload had wiped. `stop(agentId)` now takes an explicit target, a failed start refreshes the agent list, and the panel detects the orphaned runner (`phase === "idle"` with `agents[].running`) to offer a recovery card ("Stop and start" / "Stop session") plus a header stop button.
- Fixed ACP panel styling that silently did nothing: the panel used `text-primary` / `text-secondary`, which are not defined in the `@theme` block, so Tailwind v4 emitted no CSS for them and that text fell back to an inherited color (now `text-text` / `text-text/88`). `dark:` variants are also wired to the app's `data-theme` attribute via `@custom-variant dark`, so the panel's dark-mode overrides now actually apply instead of following the OS preference.
- The terminal "Add To Agent" selection action now feeds the ACP panel (restoring the legacy assistant feature): the selection shows as a removable context chip in the composer and is appended to the prompt as a fenced block; the transcript keeps it as a collapsible section on the user message.
- Web shell sessions now detect dead SSH connections (the PTY worker pumps libssh2 keepalives, so NAT/firewall idle timeouts are caught within ~20-40s instead of freezing silently) and report every abnormal PTY exit through a new `pty-closed` event. The terminal shows a non-interactive overlay with the disconnect reason and a Reconnect button (reusing the auto-reconnect flow: same server, restored working directory), disconnected tabs get a red dot, keystrokes are swallowed while disconnected, and status polling pauses for disconnected sessions.
- Docs: new [ACP Panel Frontend Guide](guides/features/acp_panel_frontend.md) (UI handoff: component map, state contract, interaction inventory, UI backlog) and [Webshell Session Guide](guides/features/webshell_session.md); the [ACP Agent Guide](guides/features/acp_agent.md) now covers the protocol support matrix, MCP bridge tools, multi-agent setup (Claude Code / Gemini CLI / Qwen Code / OpenCode), and image troubleshooting.
- SSH connection attempts can now be actively cancelled from the SSH server list while TCP connection is pending.
- SFTP browser now supports creating remote files/folders through an in-app dialog and copying absolute remote paths from the right-click menu.
- Ops Agent now supports image upload in chat, local detached attachment persistence, and click-to-view image preview for sent user messages.
- Ops Agent docs were refreshed to describe the layered package layout, multimodal request flow, and attachment storage model.
- AI provider configuration now supports explicit protocol selection with `openai_chat_completions`, `openai_responses`, and `anthropic_messages`.
- Ops Agent provider dispatch now goes through a shared interface instead of assuming a single OpenAI-compatible wire format.
- AI profile UI now shows provider icons, provider-aware defaults, and theme-aware styling for the chat footer and approval surfaces.
