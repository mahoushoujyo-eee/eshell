# eShell 1.5.4

Release date: 2026-09-18

## Highlights

### Terminal sessions recover in place

A dead PTY no longer costs you the tab. The new `reopen_shell_pty` command rebuilds
the interactive channel **on the same session id**, so the tab, its working
directory, its SFTP path and its status cache all survive a recovery.

This replaces the previous auto-reconnect, which opened a *new* SSH session and
swapped it into the UI. That path had two problems:

- **It leaked sessions.** The replaced session was dropped from the frontend list
  but left registered in the backend, so the next `list_shell_sessions` — which
  the UI renders verbatim — resurrected every orphan as a tab. A flaky link could
  accumulate a dozen of them in a minute.
- **It retried on the wrong errors.** Every operation wrapped in the reconnect
  helper (status polling, SFTP, command execution) could trigger a full session
  rebuild on any transient failure, and status polling runs every 5 seconds.

Recovery is now explicit: the terminal shows the disconnect overlay and you press
reconnect. Only a genuinely dead PTY is recoverable; a tab that was removed is
reported as gone instead of being retried forever.

### `exit` keeps the tab

Closing the shell with `exit` used to delete the session outright, leaving a tab
that could not be reconnected. The session record now survives a dead worker in
both directions — transport loss and a clean shell exit — so the reconnect button
works either way.

### Terminal clipboard shortcuts

- **Ctrl+Shift+C** copies the selection. With nothing selected the key falls
  through, so the shell still receives `^C`.
- **Ctrl+Shift+V** pastes through `term.paste`, which applies bracketed-paste
  framing so multi-line pastes are not executed line by line.

xterm binds neither shortcut: it only listens for the DOM `copy`/`paste` events,
which a WebView does not raise for its hidden textarea. Without an explicit
handler the keys reached the shell as `^C` / `^V`.

## Upgrade Notes

- No configuration or data migration.
- The session id of a tab is now stable for its lifetime. Nothing user-visible
  depends on this, but it is why a recovered tab keeps its scrollback host,
  status cache and SFTP path.
