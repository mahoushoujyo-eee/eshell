# eShell 1.5.3

Release date: 2026-09-15

## Highlights

### SSH transport rewritten on russh

- The SSH stack moves off `ssh2` (libssh2 bindings) onto pure-Rust async `russh` 0.63.3 with `russh-sftp` 2.4.0. The webshell PTY, command execution and SFTP now share one physical connection per session; `server_ops/{transport,pty,sftp,channel}.rs` carry the channel plumbing.
- `server_ops/integration_tests.rs` covers the regressions that motivated the rewrite. The tests run against an in-process russh server on loopback — no external sshd and no credentials:
  - PTY and concurrent exec calls reuse one physical connection
  - an exec request is never replayed after dispatch
  - a stale channel reconnects and still executes exactly once
  - a stalled SFTP read does not block exec on the same session
  - private-key auth, with password fallback when the key passphrase is wrong
  - a jump host carries a nested handshake and exec
- Design notes live in `docs/guides/architecture/ssh_transport.md`.

### ACP projects

- The panel's flat session history is replaced by a **project browser** (folder button in the panel header).
- A project is a local folder: one `{id, name, path}` entry in `.eshell-data/projects.json`, added through the OS folder picker. Sessions started from a project run in that folder — its path travels as the ACP `session/new` cwd, so **switching projects does not restart the agent process**.
- A pinned **Sessions** group holds everything without a project (records written before this release, plus sessions whose project was removed). It runs in the agent's own directory — `cwd` from `acp_agents.json`, otherwise the app's working directory. Removing a project keeps its transcripts; they fall back to this group.
- Session lists are **isolated per agent**: a Codex transcript is not listed or offered for resume while Claude Code is selected, because the two store unrelated sessions.

### New session without restarting the agent

- The panel header carries a **New session** button and each project row a `+`. Both send a second `session/new` on the live connection, reusing sign-in state, model/thought-level selection and the spawned process.
- The outgoing transcript is persisted to history first, so it stays readable in its project group.

### MCP: agent context tool and honest capability probing

- New `read_agent_context` tool: returns the user's global `AGENTS.md` plus the bundled `eshell-config` skill, and the server `instructions` now ask agents to call it once at session start. This is how `.eshell-data/agent/` context reaches an ACP agent — nothing is injected into the prompt.
- `resources/list`, `resources/templates/list` and `prompts/list` answer with empty, spec-shaped lists instead of a `-32601` error. Agents that probed those methods were reporting the whole bridge as "no MCP services connected"; the bridge serves tools only, which is now also stated in `instructions`.
- `resources/read` and `prompts/get` return an explicit "tools only" error rather than "method not found".

### Brand mark

- The sidebar header shows the project mark (cube + `$`, transparent background) cropped from `docs/assets/Shell.png` to `src/assets/eshell-mark.png`, replacing a generic settings icon.

## Upgrade Notes

- The SSH stack switch changes the underlying implementation of every connection (PTY, exec, SFTP, jump hosts, keyboard-interactive 2FA, private-key auth). Existing `.eshell-data/ssh_configs.json` and `known_hosts.json` files need no changes.
- New file `.eshell-data/projects.json`; it is created when the first project is added, and deleting it only clears the project list.
- Session history JSON under `.eshell-data/acp_sessions/` gains `projectId` and `cwd`. Older records lack both fields and appear under the pinned **Sessions** group; nothing is migrated or rewritten.
- `acp_agents.json` still accepts `cwd`; a project's folder overrides it for sessions started from that project.
- The panel header's history (clock) button is now the project (folder) button.
