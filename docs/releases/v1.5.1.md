# eShell 1.5.1

Release date: 2026-09-08

## Highlights

### Agent Config: AGENTS.md as editable local files

- The toolbar's **AI Config** entry is now **Agent Config**. It edits **agent context files** as real Markdown files instead of the legacy Ops Agent model profiles.
- Context lives under `.eshell-data/agent/`: a global `AGENTS.md` plus one `agent/<serverId>.md` per SSH server. A server file is created lazily on first save, edited from the dialog, and can be deleted.
- The legacy Ops Agent model configs (provider / API key / model profiles, and the AI config importer) are gone from the UI. Since the chat panel was already replaced by the ACP agent panel in 1.5.0, the entire dead Ops Agent frontend has been removed.

### Bundled `eshell-config` skill

- The `eshell-config` skill ships with the app. On first launch it is seeded to `.eshell-data/agent/skills/eshell-config/`, so a local agent (Codex, Claude Code, …) can read how to maintain eShell's own `.eshell-data` config files.

### Dependency alignment

- The `tauri` crate is aligned with `@tauri-apps/api` 2.11 and the `@xterm/addon-canvas` peer override is kept, so `npm ci` and the release build stay consistent.

## Upgrade Notes

- `.eshell-data/AGENTS.md` migrates to `.eshell-data/agent/AGENTS.md`, and `.eshell-data/server_agents/<id>/AGENTS.md` migrates to `.eshell-data/agent/<id>.md` on first launch. Both are copied only when the new target file does not already exist; the old files are left in place.
- AGENTS.md files are **editable context only** — eShell no longer auto-injects them into ACP sessions. Agents discover them via their `cwd` / skill configuration.
- `ai_profiles.json` / `ai_config.json` no longer have a UI; do not edit them by hand.
- The toolbar entry label changes from “AI Configs” to “Agent Config”.

### Known issue

`cargo test --lib` still has the 4 pre-existing `storage::tests` failures (`ai_profile_crud_works`, `get_ai_config_prefers_requested_active_profile`, `save_ai_approval_mode_updates_global_setting_only`, `save_ai_config_updates_active_profile`). They read the developer machine's real `.eshell-data/ai_profiles.json` and require a profile with a non-empty API key, so they fail on any checkout without one. Unrelated to this release; the release build runs `npx tauri build`, not these red tests.
