# eShell 1.7.0

Release date: 2026-09-28

This release redesigns the whole interface. The workspace takes its cues from
Termius and VS Code: session tabs live in the title bar, a slim activity rail
replaces the wide card sidebar, a status bar carries the session and background
state, and every panel and dialog now shares one flat, dense visual system in
both light and dark themes. It also fixes the SFTP download-folder picker,
which has done nothing since 1.6.0.

## A redesigned workspace

### Layout

- **Session tabs in the title bar.** Each tab shows a connection dot (red once
  the session drops), reveals its close button on hover, and scrolls sideways
  with the mouse wheel when there are many. `+` opens SSH Profiles. The free
  space in the title bar still drags the window.
- **Activity rail.** A 52px icon rail that expands to 220px with labels. Panel
  toggles show the panel name; the show/hide action is in the tooltip, and an
  open panel is marked with an accent bar. Settings and the collapse toggle sit
  at the bottom.
- **Status bar.** The active session, `user@host:port`, working directory,
  background activity, the latest issue (hover for the full message), and an
  "AI responding" indicator. The running/issue indicators moved here from the
  old sidebar.
- **The terminal fills its pane.** The separate tab row above it is gone and
  the working directory moved to the status bar.
- Splitters are 1px lines with a 7px grab area.

### Visual system

- **New palette.** Layered deep blue-slate surfaces in dark mode, cool grays in
  light mode, and an accent taken from the green cursor in the eShell logo.
  Body text, secondary text and the accent all meet WCAG AA contrast in both
  themes.
- **Flat surfaces.** Areas are separated by hairlines instead of nested cards,
  corners are small and consistent, shadows are reserved for floating layers
  (menus, dialogs, notices), and the background gradients are gone.
- **Bundled fonts.** Geist for the interface and JetBrains Mono for the
  terminal, code and paths ship with the app, so they render the same offline.
  Chinese text falls back to Microsoft YaHei UI / PingFang SC.
- **Terminal.** A full 16-colour ANSI palette tuned for the navy background,
  with a brand-green cursor. The terminal stays dark in both themes. New
  installs start on the plain background with frosted glass off; the
  legibility wash is now applied only when a wallpaper is active.
- **A new AI mark.** A chat bubble holding a shell prompt, whose green cursor
  blinks while the agent is responding. It replaces the generic sparkles icon
  in the title bar, the status bar and the terminal's "Add To Agent" button.
- **Notices** appear bottom-right, above the status bar, tinted by an ambient
  glow in their tone colour. They are now readable in dark mode, where the old
  hard-coded light colours were not.

### Panels

- **SFTP** — a compact icon toolbar with tooltips, a monospace path, a search
  filter, denser tree and file rows with a sticky header, a transfer queue that
  opens as a popover, and a flat context menu.
- **Server status** — thin resource bars that turn amber at 75% and red at 90%,
  network rates on their own row, and segmented controls for the refresh
  interval and the detail view. The panel adapts to narrow widths instead of
  wrapping or clipping.
- **Command draft** — a shared panel header with the Ctrl+Enter hint and a
  compact footer.
- **AI panel** — tool calls and thinking collapse into compact rows coloured by
  status, agent replies read as plain text next to a soft user bubble, and the
  composer, agent picker and session menus share the new styling. Markdown
  lists now render their bullets.

### Dialogs

All fourteen dialogs share one dialog component: an icon title row, a
scrolling body, a footer, and the same buttons and fields everywhere.

- **SSH Profiles** is a host list: name, authentication and jump-host badges,
  and a monospace `user@host:port`. Edit and delete appear on hover; Connect is
  always visible. The form is grouped into server, authentication (a segmented
  selector) and jump host.
- **Scripts** uses the same list style. **Agent Config** and **Settings** are
  two-pane layouts with a navigation rail and grouped rows. The wallpaper
  picker, crop dialog and file editor (with an Edit/Preview switch) follow the
  same design.
- **Escape** now closes the SSH, script, agent, wallpaper and crop dialogs, and
  only the topmost dialog responds: pressing Escape on the plugin removal
  confirmation no longer closes Settings behind it.
- The host-key trust and keyboard-interactive prompts still require an explicit
  answer and ignore clicks outside them.

The design rules and tokens are written up in
[docs/plans/ui-redesign-termius.md](../plans/ui-redesign-termius.md).

## Fixes

- **The transfer queue's "Change" button opens the folder picker again.** Since
  1.6.0 the builtin SFTP panel picks its download folder through its plugin
  API, but the workspace never handed the panel that API, so the click
  silently did nothing. A regression test now clicks through the real path.
- Collapsing the sidebar left the Settings button full width; it now collapses
  to an icon with the rest of the rail.

## Server status

The 1-second refresh interval is gone; the choices are 3, 5 and 10 seconds.

## Backend

- The Rust backend is reorganized into per-domain modules — `ssh`, `sftp`,
  `config`, `scripts`, `ai`, `monitor`, `extensions` and `ops_agent` under
  `src-tauri/src/domain/`, each split into model, service and command layers —
  with shared error, time and logging code in `common/`.
- The self-hosted Ops Agent runtime is removed. All agent work goes through
  external agents over the Agent Client Protocol, which the ACP panel already
  handled.

## Example plugins

- **New `examples/k8s-plugin/`** — a kubectl client for the active SSH session's
  host. Any resource type in any namespace or context (tabs for the common ones,
  a box for CRDs), listings rendered from `kubectl get -o wide`, status colouring
  read from the cells themselves, logs with a container picker, non-interactive
  `exec`, describe / `-o yaml` / events / explain, scale, rollout restart /
  status / history / undo, CronJob suspend and manual runs, node cordon /
  uncordon / drain, `kubectl top`, bulk delete, and `kubectl apply -f -` with a
  server-side dry run.
- **`examples/docker-plugin/` grew into a full Docker client** — volumes,
  networks, Compose projects, `docker events`, a System tab over `docker info` /
  `docker version` / `docker system df` with every prune variant, a `docker run`
  form with a live command preview, non-interactive `exec`, bulk container
  actions, live `docker stats`, and Docker Hub search. Listings now read
  `--format '{{json .}}'` instead of tab templates.
- Both plugins follow the app's language (English / 简体中文) by observing
  `<html lang>`, ship their own icon, and keep every destructive action behind a
  confirmation that shows the exact command it will run.

## Upgrade Notes

- **No data migration.** `.eshell-data` files keep their existing formats and
  locations.
- **Your saved choices are kept.** An existing expanded/collapsed sidebar
  preference and a chosen wallpaper carry over; only new installs start with the
  collapsed rail and the plain terminal background.
- A saved 1-second status refresh interval falls back to the 5-second default.
- Leftover `ops_agent_*` files in `.eshell-data` are no longer read and can be
  deleted.
- **Plugin authors:** every existing theme class (`bg-panel`, `text-muted`,
  `bg-accent`, …) still exists, and plugin panels pick up the new palette
  automatically. New tokens are available: `elevated`, `border-strong`,
  `subtle`, `info`, `hover` and `on-accent`. Put `text-on-accent` rather than
  `text-white` on `bg-accent` — the dark-theme accent is bright, so white text
  on it is hard to read. The bundled examples already do.

## Validation

Validated locally with:

- `npm run test` — 364 passing
- `npm run build` (vite)
- `cargo test --lib` — 239 passing (fewer than 1.6.0's 300 because the removed
  Ops Agent runtime took its tests with it)

The redesign was reviewed in a browser preview against a stubbed Tauri backend:
both themes, the Windows and macOS title bars, a narrow window with three
bottom panels, a dropped session, and the empty state. Manual verification in
the desktop window is still recommended for dragging the window from the tab
strip, WebView2 loading of the bundled fonts, and the native folder picker.
